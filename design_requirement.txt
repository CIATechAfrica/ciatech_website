# CIATECH AFRICA: DESIGN & ARCHITECTURE REQUIREMENTS

## 1. PROJECT OVERVIEW
- **Project Name:** CIATECH Africa Corporate Platform
- **Site Type:** Development-driven social enterprise / NGO website.
- **Core Mission:** Designing scalable solutions for Africa's development challenges, operating at the intersection of technology, entrepreneurship, and systems change.

## 2. DESIGN & UI/UX GUIDELINES
- **Aesthetic:** Modern, premium, and clean. Emphasizes an optimistic, dynamic African context (youth collaborating in tech hubs, digital agriculture, green innovation).
- **Brand Palette:** 
  - Primary Base: Warm Browns & Earthy Tones (`#8E5516`).
  - Secondary/Accent: Vibrant Gold (`#E2AD00`).
  - Backgrounds: Clean whites (`#FFFFFF`) and structured grays (`gray-50`).
- **Typography & Components:** Smooth, deeply rounded image corners (24px+), split-color typography for emphasis, heavy use of bold typography for metrics (Impact Stats), and micro-animations for interactivity (shadow lifting on hover).
- **Sanity Studio UI:** Custom CIATech branded theme, categorized navigation (Pages, Content, Inbox, Settings), and visual status indicators for form submissions.

## 3. ARCHITECTURE STRATEGY
- **Architecture Pattern:** "Hub & Spoke" (Decoupled Headless CMS)
  - **The Hub (Homepage):** Exists strictly as a teaser funnel. Displays high-level summaries of core pillars and top solutions with clear "View All" or "Partner With Us" call-to-actions.
  - **The Spokes (Interior Pages):** Detailed, isolated content routes (`/solutions`, `/research`, `/opportunities`, `/impact`, `/about`).
- **Data Layer (Sanity CMS):** Strict separation of content from UI components. Content is managed in a fully integrated Sanity backend.
- **API & Mutation Layer:** Next.js Server Actions securely process form data, validate it using Zod, and trigger third-party integrations (Resend).

## 4. DEVELOPMENT PHASES
- **Phase 1: Static Architecture & Atomic Components (Completed)**
  - Establish Next.js App Router and Tailwind v4.
  - Create the UI component library and static routing.
  
- **Phase 2: Dynamic Systems Integration (Completed)**
  - Transition the Mock CMS data into a fully integrated Sanity Headless CMS.
  - Dynamic routing, content hydration, and Server Action form submissions.
  - Resend transactional email integration for admin notifications and user auto-replies.

- **Phase 3: Security, Quality Assurance & Studio UX (Completed)**
  - Implement strict runtime validation on Server Actions using Zod schemas.
  - Overhaul Sanity Studio UX for a premium administrative experience.
  - Establish testing pipelines using Vitest (Unit) and Playwright (E2E).

- **Phase 4: Optimization & Deployment (Upcoming)**
  - Transition synchronous email tasks to background queues for lower latency.
  - Finalize production deployment (e.g., Vercel) and verify custom domain DNS records.

## 5. TECH STACK
- **Framework:** Next.js (App Router, v15+)
- **Language:** TypeScript
- **Styling:** Tailwind CSS (v4)
- **CMS / Database:** Sanity.io
- **Email API:** Resend
- **Validation:** Zod
- **Testing:** Vitest & Playwright
- **Icons:** Lucide React
